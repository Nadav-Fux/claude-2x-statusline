Custom — pick your segments

Create ~/.claude/statusline-config.json and toggle each segment on/off (29 segments total; a few of the newer ones are shown here — see docs/FIELDS.md in the repo for the full list):

{
  "tier": "custom",
  "segments": {
    "model": true,
    "context": true,
    "git_branch": true,
    "git_dirty": true,
    "cost": true,
    "effort": true,
    "rate_limits": true,
    "tool_count": true,
    "peak_hours": false
  }
}

peak_hours is the old promo_2x-era segment (the legacy key is still accepted). It's off by default in every tier now that Anthropic dropped peak-hour throttling — flip it on here if you're running a custom schedule.

Recent fixes & additions

VS Code / Cursor / Windsurf / Antigravity cockpit — v0.4.0

Providers render in a fixed priority order (Claude → Codex → Antigravity → GLM+Copilot → Droid); the bar greedily appends them left to right and stops before it would blow its length budget (80 characters by default, configurable). A dropped provider isn't lost — it moves into the tooltip, which always shows the full truth: every provider's plan, window, %, and reset time, plus a note listing what the budget cut. GLM and Copilot now share one combined bottom row instead of two separate lines.

Terminal statusline — "super-status" additions

The Full-tier metrics line gained eff ●●●●○ cache-efficiency dots, a ⚒ tool-call counter, and a small multi-CLI clock. Rate-limit and quota bars now use window-aware color thresholds — short windows like 5h trip red/yellow at 80%/50%, while weekly/monthly-style windows (and GLM's token quota) use 75%/45% since they cover much more time. Every installer/doctor write to settings.json now backs it up to a timestamped .bak file first.

Antigravity provider

Fixed a precedence bug where the CLI fallback's 5h-only view could clobber a richer, already-cached quota summary (both pools, 5h + weekly). The CLI fallback now writes to its own cache file, so it can never overwrite the primary summary again.

Narrator — accurate on 1M-context models

Fixed a false "context is maxed" warning on 1M-context sessions at low real usage. Root cause: a context-snapshot file shared across sessions could leak a different session's reading, and a rolling-token fallback assumed a 200K window. Fixed by rejecting any other session's file outright and gating that fallback to windows above 200K — a genuine 200K session already has the real reading from the bar itself.
