# רקע

החלטות עיצוב והקשר היסטורי המסבירים מדוע הקוד מאורגן כפי שהוא.

## למה שלושה מנועים?

הפלאגין מיועד למפתחים שעשויים להחזיק בכל שילוב של Python, Node.js או Bash בלבד. Python מעניק את מלוא התכונות (narrator עם תמיכת Haiku). Node.js מספק זוגיות מלאה של שורת הסטטוס למפתחי JavaScript שאולי אין להם Python מותקן. Bash הוא ה-fallback האוניברסלי המרנדר שורת סטטוס מינימלית אך פונקציונלית.

תחזוקת שלושה מנועים היא החלפה מודעת: נטל תחזוקה רב יותר, אך אפס חיכוך למשתמשים ללא תלות בסביבת הריצה שלהם.

## למה schedule מרוחק?

Anthropic שינתה את מדיניות ה-rate-limiting וה-peak-hours מספר פעמים. הטמעת שעות שיא בקוד הייתה דורשת מהמשתמשים לעדכן בכל פעם שהמדיניות משתנה. על ידי אחסון `schedule.json` ב-GitHub, המתחזק יכול לעדכן קובץ אחד וכל שורת סטטוס פעילה תאסוף את השינוי תוך 3 שעות.

עיצוב זה גם מאפשר דחיפת באנרים פרסומיים ו-feature flags ללא שינויי קוד.

## למה פלט narrator ממוסגר?

ה-narrator עוטף את הפלט שלו בתוחמים `//// -> text ////`. לכך שתי מטרות:

1. הבחנה ויזואלית מהקשר הפרומפט הרגיל, כך שהמשתמש יודע שזוהי תובנה מוזרקת, לא טקסט שלו עצמו
2. יציבות פרסור עבור עיבוד הפרומפט של Claude Code

## למה ניקוד ב-4 צירים?

מערכת הניקוד של ה-narrator משתמשת בארבעה צירים (urgency, novelty, actionability, uniqueness) במקום תור עדיפויות פשוט. זה מונע מאותה תובנה לחזור על עצמה (novelty), מבטיח שעצה מעשית מדורגת גבוה יותר ממידע טהור (actionability), ונמנע מהשמעת עובדות שהמשתמש כבר רואה בשורת הסטטוס (uniqueness).

## למה חלונות מתגלגלים במקום ממוצעי סשן?

ממוצעי סשן מטעים במהלך סשנים עם פעילות פרצים. אם משתמש מוציא $5 ב-10 הדקות הראשונות ואז נח, הממוצע המצטבר נשאר $30/hr גם שעות אחר כך. חלון מתגלגל של 10 דקות לוכד את מהירות ההוצאה הנוכחית, שזה מה שהמשתמש באמת צריך לדעת.

מגיני ה-spike (מגבלת $200/hr, מינימום 3 דקות) נוספו לאחר שארבעה באגי overflow מספריים נפרדים יצרו ערכים אבסורדיים בבדיקות מוקדמות.

## למה כתיבת קבצים אטומית?

שורת הסטטוס רצה לעיתים תכופות (כל פרומפט). אם התהליך מופרע באמצע כתיבה ל-`statusline-state.json` או `narrator-memory.json`, קובץ פגום יישאר וישבור הרצות עוקבות. דפוס tmpfile + rename מבטיח שהקובץ יהיה או כתוב במלואו או ללא שינוי.

## למה לדחות stubs של WindowsApps?

ב-Windows, הפקודה `python3` ב-`WindowsApps/` אינה Python. זהו alias של Microsoft Store שפותח דיאלוג התקנה. אילו ה-resolver היה מקבל נתיב זה, שורת הסטטוס הייתה נכשלת בשקט בכל מכונת Windows שאין בה Python מותקן במפורש. דחיית stubs אלה וזיהוי מיקומי התקנה ניידים מבטיחים ששורת הסטטוס עובדת בהתקנות Windows טריות.
